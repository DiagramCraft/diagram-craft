# Workspace Templates And Capabilities

Workspace templates provide a starting model when creating a workspace. Applications and capabilities configure
workflows for an existing workspace. These are related setup choices, but they serve different purposes.

## Create A Workspace From A Template

Users with the global permission to create workspaces can open the workspace selector and choose **New workspace**.
Start blank, choose one full architecture template, or combine a full template with one or more cross-cutting concerns.
The template selection screen describes the available starting models.

A template can contribute entity and typed-relation schemas, enums, shared field groups, document types and templates,
saved views, and authored entity drawer profiles. Cross-cutting concerns can depend on schemas from the selected full
template. Resolve each dependency to a destination schema during workspace creation; an unresolved required mapping
prevents creation. Concern dashboards remain separate from the full template's Overview dashboard.

To add a concern to an existing workspace, open **Workspace Settings → Export & Import → Definitions** and use the
definition import flow. Review the proposed mappings and resolve dependencies before applying the import.

## Configure Applications And Capabilities

Open **Workspace Settings → Applications & Capabilities**. Applications are workspace data: the built-in applications
(Business Glossary, Strategy & Capability Modelling, Vendor Management, Risk & Compliance, Data Stewardship, API &
Integration Catalog) are created with every workspace and can be edited or deleted like any other application.

Use the **+** button in the sidebar to add an application. The **Add application** dialog asks for a name, a key, an
optional description, and an accent colour. Each application then has two tabs:

- **General** — name, description, accent colour, and **Delete application**. Available to users with
  dashboard-management rights.
- **Access** — who can use the application. Available to workspace administrators. The policy can allow all workspace
  members or selected people and teams. Individual and team grants are additive.

The access policy is separate from workspace roles: members still need workspace access. A missing policy denies
ordinary members; global administrators and workspace role managers retain access. Home remains available to workspace
members.

Dashboards inside an application are managed from its left rail, not from this screen.

Capabilities are listed separately. Workspace templates connect the **API specification** capability to the API schema
when the template is applied; its **Binding** tab, under *Capabilities*, edits the connection. Other applications are
dashboard-based and need no binding.
