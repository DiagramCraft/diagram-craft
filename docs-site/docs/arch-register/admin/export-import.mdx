# Export And Import

Export and import are administrative operations because they move or reshape workspace data at a broader scope than
normal editing.

Open **Workspace Settings → Export & Import**. These operations require workspace administration access. Review the
archive contents and import preview before applying changes, especially when moving data between workspaces with
different schemas or permissions.

## Workspace-Level Operations

The workspace settings area includes export and import for moving data between workspaces or creating a packaged
snapshot.

Workspace archives can include entity schemas and entities together with typed relation schemas and relation instances.
Relation field values follow the same field-group redaction rules as entity values. When an entity filter excludes one
of a relation's endpoints, that relation is omitted and the archive manifest records a diagnostic; imports also preview
missing relation-schema or endpoint dependencies before writing data.

The archive format remains version `1.0`. Relation files are optional, so older archives without typed relation sections
continue to import. Relation history and approval-case records are not included until relation versioning and approval
workflow support is delivered.

### Applications

Select **Applications** (applications, dashboards and access policies) to include the workspace's applications in the
archive. They are written to `applications.json` and contain:

- each application's key, name, description, and accent colour, in order
- each application's ordered dashboards, including widgets, sidebar, icon, and rail label
- each application's access policy as a mode (all members or selected) and the selected teams
- the workspace home dashboards

Individual users are not exported, so imported policies keep only their team grants. Personal and project dashboards
are not included. The section is optional, so archives without it continue to import.

On import, applications are matched by key. The import preview shows the application and dashboard counts and any
conflicts; resolve each conflict by skipping, overwriting, merging, or renaming. Schema references in dashboard
widgets and teams in access policies follow the remapped schemas and teams of the destination workspace.

## Entity-Level Operations

Entity CSV import and export are documented with the entity workflows because they are narrower operational tools tied
to the catalog browser.

## Keep The Distinction Clear

Use:

- workspace export/import for workspace-wide movement
- entity import/export for schema-oriented catalog operations
- definition import for bringing supported templates or cross-cutting concerns into an existing workspace; resolve
  schema dependencies in the import preview before applying them
