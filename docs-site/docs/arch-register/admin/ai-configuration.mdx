# AI Configuration

> **Experimental:** Arch Register's AI features are experimental. Their availability and behavior may change.

AI configuration is workspace-scoped and controls Assistant, Extract, document AI actions, and metadata generation.
Members with `ws.settings` can configure the provider and model once for the workspace; individual users still act
through their own permissions.

## What You Configure

The current UI exposes configuration for:

- whether AI is enabled
- provider selection
- API key or equivalent credentials
- model
- temperature
- optional system prompt

Choose a provider supported by the deployment and supply valid credentials and a model name. Users can access AI
features only when workspace AI is enabled, provider configuration is valid, and their normal workspace permissions
allow the requested data.

## Operational Notes

The workspace prompt is shared configuration, not a per-user preference. Treat it as a workspace behavior control and
manage it accordingly.

Workspace API keys are stored using a versioned encrypted format. Configure `AI_ENCRYPTION_KEY` before saving a key;
new plaintext credential writes are rejected. For legacy values or key rotation, run the server's
`rotate:ai-keys` command in `--check` mode and then `--apply` mode with the appropriate `--legacy-format` and old-key
environment variables. Do this during a maintenance window, and remove the old key after successful migration.

AI metadata generation is asynchronous. The separately deployed job server must use the same `AI_ENCRYPTION_KEY` as
the main server to read workspace credentials. See [Scheduled Jobs](scheduled-jobs) for worker setup and run monitoring.
Generation writes a validated value to the configured AI-managed document field automatically; it does not wait for a
user to approve each result. Interactive Assistant writes and Extract results have separate review or approval steps.
