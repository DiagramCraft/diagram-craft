# Assessments

Assessments collect structured review data about entities in a project. Use one for a repeatable checklist, scorecard,
or confirmation that existing entity data is accurate. You can review responses from the project assessment grid or
from an entity's detail screen.

## Find An Assessment

Open a project and select **Assessments** in its sidebar. The list groups assessments as **Draft**, **Open**,
**Closed**, and **Archived**. Draft assessments are still being configured; open assessments accept responses; closed
assessments keep their results available for review; archived assessments are separated from the main list. Open and
closed assessments show completion progress.

Creating, editing, or changing an assessment's status requires edit access to its project. Project access follows
workspace project capabilities and the project owner's team role. See [Roles And Permissions](../admin/roles-permissions).

## Define Scope And Fields

Select **New assessment** to start from scratch or from a built-in template. Templates provide editable suggested names,
descriptions, scopes, and fields:

- **Business fit vs. technical fit** has required 1–10 Business fit and Technical fit ratings plus a calculated
  **TIME quadrant** (Tolerate, Invest, Migrate, or Eliminate).
- **6Rs migration strategy** has a required selection for Rehost, Replatform, Refactor / Rearchitect, Repurchase,
  Retire, or Retain.
- **Pace Layering** has a required selection for Systems of Record, Systems of Differentiation, or Systems of
  Innovation.

The **Scope** tab selects the entity types in the project that the assessment covers. Add optional filters such as
owner, lifecycle, namespace, or schema fields to narrow the set; the conditions are combined with AND logic, and the
editor previews the number of matching entities. Filters can use only fields you are allowed to view. If your access
does not include a restricted field used by an existing condition, that condition is hidden and fails closed for you.
Changing scope can add or remove entities from the assessment view, but it keeps existing responses.

Use **Fields** to define the response data:

- **Rating** is 1–5 by default and can be configured up to 1–10.
- **Select** stores one value from a workspace enum or assessment-local options.
- **Notes** stores free text.
- **Derived** calculates a read-only value from other assessment fields.

Mark response fields **Required** or **Optional** and optionally arrange them into named groups. Groups only affect how
fields are presented; they do not change the assessment grid or results. Derived fields are optional and do not affect
completion status. Choose **Confirm only** as the completion mode when reviewers should confirm entity data rather than
fill in fields; confirm-only assessments do not accept field values.

## Assign Teams And Set A Schedule

In the editor's **Assignment** tab, you can assign one or more teams and set an optional due date while the assessment
is a draft. When it opens, each assigned team receives an acknowledgement task in [My Work](governance). Closing the
assessment resolves those tasks. The Summary tab shows each team's acknowledgement status. Assigned teams and the due
date are locked while the assessment is open; return it to draft to change them. Team assignment does not itself grant
permission to edit the project or record responses.

The **Advanced** tab can make an assessment one-off or recurring weekly or monthly. Set the interval in weeks or
months (for example, every three months) and, for recurring assessments, a response window in days. The interval
determines when the next response cycle opens; the response window sets its due date. Each new cycle starts with fresh
completion progress while preserving earlier responses for history. The assigned teams receive a new acknowledgement
task for each cycle, and the assessment card shows its current cycle and next opening date.

## Record Responses

Open an assessment to see every in-scope entity in the **Details** grid. The assessment must be **Open** to record a
response. Recording responses requires edit access to the project. Reviewers can also respond from the entity's
**Assessments** tab when an open project assessment applies to that entity.

In field-based assessments, **Not started** means no required fields are filled in, **In progress** means some required
fields are filled in, and **Complete** means all required fields are filled in. An assessment with no required fields
is complete by definition. In confirm-only mode, each in-scope entity is either unconfirmed or confirmed. Use the grid's
status filters, search, field filters, sorting, and inline editing to work through the scope. Closed assessments remain
available to inspect but do not accept new responses.

## Review Results And Export

Select the **Summary** tab to review response counts and aggregate field results. Rating fields show averages, select
fields show value distributions, and notes fields show how often a value was entered. When teams are assigned, the
summary also shows their acknowledgement status.

Choose **Export CSV** from the assessment menu to download one row per in-scope entity, with standard entity columns
and one column per assessment field. Entities with no response are included with blank assessment cells. Exported
rows and scope-derived results follow your field access; information based on scope conditions you cannot view is
omitted.

## Use Assessment Data In Entity Views

The entity browser can join one assessment at a time. Joined assessment fields appear beside normal entity fields and
can be used for sorting, filtering, and analysis. Changing or clearing the joined assessment removes filters and view
configuration that referenced the previous assessment's fields. See [Entity Views](entity-views).
