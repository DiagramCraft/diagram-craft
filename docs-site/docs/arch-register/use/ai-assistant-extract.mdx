# AI Assistant And Extract

Arch Register exposes two AI-facing sections in the workspace shell: **Assistant** and **Extract**. Document types
can additionally define AI actions that run directly from a document.

> **Experimental:** Assistant, Extract, document AI actions, and AI metadata generation are experimental features.
Their behavior and availability may change.

## Assistant

Assistant is the conversational workspace screen. Use it when you need:

- help reasoning about workspace data
- guided exploration across entities and projects
- AI-supported drafting with workspace context

Assistant behavior depends on workspace AI configuration, including provider, model, and optional system prompt.
The assistant can search and inspect records that you are allowed to view. If you ask it to create or change an entity
or relation, review the proposed change and explicitly approve it before the write runs. The usual workspace,
entity, and field-group permissions still apply.

## Extract

Extract is the structured AI flow for turning supported input material into proposed architecture records. Review the
detected fields, adjust each proposed entity name, and choose which records to accept. Arch Register creates only the
records you accept, subject to your normal workspace and schema permissions. Treat Extract as a focused workflow
rather than a general chat interface.

## Document AI Actions

Document types can define interactive AI actions. When a document's type has actions configured, anyone who can view
the document can launch them from the document sidebar.

An action runs its predefined prompt read-only against the document's body, structured metadata, type, and location —
it never modifies the document. Each action can be restricted to a selected subset of the read-only architecture
tools. Tool use is additionally limited by the initiating user's normal permissions. The result is temporary; if it is
worth keeping or exploring further, continue it as an Assistant conversation from the result panel.

Actions are defined per document type in
[Document Types and Templates](../admin/document-types-templates).

Document types can also define AI metadata generators. Unlike interactive actions, a generator runs after a document
change and automatically writes its validated result to its configured AI-managed field. The result and its
generation details remain visible on the document; changes to the document mark the result outdated. Administrators
configure generators in [Document Types and Templates](../admin/document-types-templates).

## Availability

These sections are experimental workspace features, not guaranteed defaults. If they are missing, check:

- whether AI is enabled for the workspace
- whether your role exposes the feature
- whether the workspace has valid provider configuration
- whether you have workspace view access and permission to view the relevant records
