# Content

Arch Register content includes wiki pages, diagrams, uploaded files, and folders. Choose the scope that matches the
work: workspace content is shared across the workspace, project content belongs to an initiative, and entity content
stays with one catalog record.

Workspace and entity content use the workspace's `content.view` and `content.edit` capabilities. `content.view` allows
members to view and download content; `content.edit` allows them to create, update, move, and delete it. Project content
uses project and owner-team access instead. Workspace content capabilities do not grant access to project content. See
the [Scope Matrix](../reference/scope-matrix) and [Roles And Permissions](../admin/roles-permissions) for how those
boundaries work.

## Workspace Content

Use workspace content for standards, shared documentation, and diagrams used across the workspace. Open **Content**
from the workspace navigation to organize folders, pages, diagrams, and uploads.

## Project And Entity Content

Project content is scoped to one initiative and follows that project's access rules, including its owner-team roles.
Open the project's content tree to create folders, documents, diagrams, and uploads for the initiative. See
[Projects](projects) for the project dashboard and planning workflows.

Entity content is attached to an individual record and uses workspace `content.view` and `content.edit` capabilities.
Open the entity's content area to add or review record-specific notes, diagrams, and files. Entity content access is
separate from access to restricted entity fields.

## Wiki Pages, Documents, And Attachments

Use a wiki page for lightweight documentation that you want to edit in Arch Register. Use an upload when the original
file should remain intact. Supported attachments can be added to Markdown and document content; document links and
backlinks help readers move between related pages. Inline comments keep review discussion attached to supported
content.

Markdown documents can be untyped or use a [document type](../admin/document-types-templates). A type adds structured
properties such as status, dates, numbers, and links to entities or other documents. Required properties are validated
when a document is saved; expected properties produce a warning. When creating a wiki page, choose a type and optionally
a template. Workspace templates are available across the workspace, while project templates are available in their
project. Templates can prefill the Markdown body and metadata, including `{{title}}` for the new document name. Untyped
Markdown remains available for content that does not need structured properties. If a document type is archived,
existing typed documents keep their metadata and type history.

## Rich Content Blocks

The Markdown editor supports more than plain text:

- **Diagram and image embeds** for diagrams and uploaded images
- **Live entity blocks** such as entity cards, tables, charts, metrics, changelogs, browsers, and saved views, which
  render current catalog data inside the page
- **Entity graphs** for compact, read-only dependency or impact graphs:

  ```mdx
  <EntityGraph id="APP-001" depth="2" direction="both" />
  ```

  `id` accepts an entity public ID or UUID, `depth` is `1–3` (default `1`), and `direction` is `upstream`,
  `downstream`, or `both` (the default). Nodes link to the entity, and a truncated graph links to its full Graph view.
- **Inline references** such as entity mentions, entity links, and live entity field values
- **Layout blocks** such as callouts, foldable sections, columns, tabs, captions, and labels

Glossary term usage and backlinks are collected from explicit links in Markdown metadata, project associations, and
diagram entity references. They include only links visible to you; see the
[Business Glossary guide](../applications/guides/business-glossary).

## Diagrams And Previews

Create a diagram at the workspace, project, or entity scope where it belongs. Open its preview to inspect the stored or
generated diagram and its metadata. When the Diagram Craft integration is configured, open an associated diagram in
the Diagram Craft editing experience.

## Revisions And History

Supported documents keep revision history. Open a document's **History** view to inspect earlier revisions, compare
them, or restore a previous version. Typed documents also retain their structured metadata and document-type history.
Project baselines are read-only snapshots of entity and relation state; they are separate from document revisions. See
[Entity Baselines](entity-baselines) for those snapshots.

## Experimental External Content

External content mounts are experimental. The current workspace **Content → New → Mount Git repository** flow
synchronizes a selected path from a public HTTPS Git repository into workspace content. Repository authentication is
not supported, and mounted content is read-only in Arch Register. The mount can be configured with a refresh interval;
its sync status is available from the mount's actions menu.

For deployment-specific integration patterns and related setup guidance, see
[External Integrations](../reference/external-integrations).
