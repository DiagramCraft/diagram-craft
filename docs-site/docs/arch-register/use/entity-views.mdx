# Entity Views

Use the entity browser to find a catalog slice, choose how to inspect it, and save the configuration for repeat work.
The browser is available from **Entities** and in project entity scope. Your workspace and entity permissions determine
which records and fields appear.

## Filter And Sort Entities

Start with the sidebar facets for schema, lifecycle, and owner. You can select several values in a facet; those
selections are alternatives, while selections in different facets narrow the results together. Use the search box for
text matches, then open the filter builder for field conditions or a structured query. The Simple/Advanced switch lets
you edit the query as text when you need boolean groups or relationship traversal. In a project browser, use **Scope**
to show project entities or all entities.

Use **Sort** to choose an available entity field and sort direction. In **Manage fields**, choose the fields shown by
the table. Assessment fields can be added by joining an assessment; this is useful for reviewing answers beside
catalog data. See [Assessments](assessments) for the project assessment workflow.

## Table, Cards, And Tree

### Table

Use the table for auditing, sorting, and comparing fields side by side. Select rows for bulk actions, or choose fields
in **Manage fields** to focus the table on the information needed for the task. Project context can add project-only
fields such as project role and project status.

## Choose Another View

The **View** menu includes specialized screens. Each view keeps the current entity query and scope while presenting the
matching records for a different task:

- Use [Relationship Views](entity-relationship-views) to follow connections with Graph, Topology, Explore, Matrix,
  Traceability, or Path Walker.
- Use [Planning And Portfolio Views](entity-planning-views) to compare distributions, dates, changes, and metrics
  with Radar, Timeline, Diff, Bubble, Heatmap, or Map.

## Save And Reuse A View

Members with saved-view management permission can open the entity browser actions menu and choose **Save View As...**
to name the current view. A saved view retains its query, sorting, display fields, selected display mode, and that
mode's configuration; joined assessment data is retained as well. When working in a project, choose the available
workspace or project scope. Workspace views can be pinned for other members when the permission is available.

Select a saved view in the sidebar to restore its filters and configuration. When the active saved view changes, use
**Save View** to update it; use the view menu to rename or remove saved views. Saved views can also be embedded in
workspace dashboards and wiki pages. See [Workspace Dashboards](workspace-dashboards) and [Content](content) for those
workflows. Workspace templates may also provide starter views for their schemas.

## Import And Export

The entity browser also supports CSV workflows: export the current browser slice, import entities through a review
screen before anything is written, or download schema-specific templates to prepare data outside Arch Register.

## Technology Lifecycle Example

Technology Release records can be reviewed in a table for support dates, in Radar by technology category and lifecycle
status, or in Timeline by release and end-of-life dates. These are release-level views; filtering applications by the
support state of referenced releases requires relationship-aware reporting. The Default workspace template and seeded
workspace include the Technology Release catalog.
